# NASA GMAT starfield research package v01

Prepared and verified offline on 2026-11-14. This is a standalone research and integration payload, **not an integrated or rendered Unity sky**. No Unity compile, build, gameplay or visual verification is claimed for these examples. Target project: Unity 6000.3.28f1, URP, Windows x64.

The package contains 2,797 selected rows from the 42,100-row star graphics asset distributed with NASA GMAT. Source commit: `b8aec552a8f34a9212063adc3f249bd2315397a3`. The original bytes, source-reading evidence, full Apache-2.0 licence and modification notice are included. No HEASARC BSC5P catalogue data, comparison anchors, BSC converters, mixed verification logs or preview are included.

## Verify offline

Python 3.10+ and its standard library are sufficient. From this directory:

```powershell
python -B verify_package.py
```

This command reads only local files and writes nothing. Do not use `python -O`, which disables Python assertions. `verification.json` records the executed result. `manifest.json` inventories every payload file with its byte size and SHA-256. `SHA256SUMS.txt` also includes the manifest; neither inventory hashes itself. The local `.gitattributes` preserves source and generated bytes across Git checkouts.

`gmat_catalogue.py` verifies its source hashes and byte-identical CSV/JSON regeneration by default. `--build` deliberately rewrites only the two derived star files. `--fetch` deliberately retrieves the four exact pinned GMAT sources, refusing changed bytes or a file larger than 1.5 MB. These options are not part of ordinary verification.

`geometry.py` verifies the nine authored geometry samples by default; `--build` deliberately regenerates `planet-samples.json`. `horizons_reference.py` verifies and regenerates the copied CSV in memory from the exact NASA/JPL raw response; it has no network or refresh action.

GMAT coordinates are RA/declination in degrees. Alignment with J2000 is **inferred** from the upstream renderer's conversion of constellation borders from B1875 to J2000; the original stellar observation epoch and measurement provenance are unspecified. Do not call this an epoch-of-date sky, precision astrometry, Johnson-V photometry, or an independently validated catalogue. Proper motion, stellar parallax, aberration and frame bias are not modeled. Decimal places preserve conversion reproducibility, not observational accuracy.

The celestial mapping is `Unity(x,y,z) = ICRF(y,z,x)`: +Z is RA 0/Dec 0, +X is RA 90/Dec 0, +Y is celestial north. Unit directions use `(cos(dec)*sin(ra), sin(dec), cos(dec)*cos(ra))`. The source's coarse visual magnitudes map to `10**(-0.4*m)` relative flux. This is a brightness convention, not calibrated exposure. B-V is absent (`null`), so any neutral-white display is artistic. Polaris retains source magnitude 6.0; upstream's special `-2` renderer override is not applied. There are 12 repeated exact coordinate pairs: a renderer should coalesce coincident positions at the brightest source value rather than sum duplicate brightness.

Horizons uses Mars body center 499 relative to Earth center 399, ICRF with `REF_PLANE=FRAME`, kilometres/seconds and `VEC_CORR=NONE`. UT means UTC for these dates; the raw future leap-second caveat is preserved. These are simultaneous geometric positions, with no apparent-place corrections. Treating the inferred GMAT celestial alignment as ICRF is an educational visual approximation.

The near-Mars sample is constructed 50,000 km from Mars while preserving exactly the same Earth range as the reference Mars center. This makes its frozen light time compatible with the existing C04 reference, without calculating an orbit. The midpoint and 20,000 km Earth-departure cases are comparisons only and have different Earth ranges. At the first near-Mars epoch, Earth is about 13.29 arcseconds across and Mars about 7.77 degrees across; they are about 90 degrees apart. The Mars radius is 3,389.50 km and Earth radius 6,371.0084 km; spherical angular diameter is `2*asin(radius/distance)`.

Light time uses `c = 299792.458 km/s`; `2*distance/c` is a frozen-geometry round-trip floor within this simplified model. It excludes moving endpoints, processing, scheduling, occultation and RF limits. It must not be presented as an exact moving-endpoint propagation time. The indices map to elapsed day 0, 30 and 31; if the UI starts at Day 1, Day 31 uses index 30. Earth-Mars range decreases through this snapshot.

## Integration boundary and provenance

The integrator must choose the authoritative observer and mission epoch, bind source directions to the existing presentation, and use one ship-to-celestial orientation for stars and planets. Subtract kilometre-scale positions in double precision before conversion to a float direction; do not place celestial bodies at astronomical-unit-scale Unity float positions. Camera or window changes must not relocate the sky. No runtime contracts, shared gameplay state, scene, package settings or Unity asset GUIDs are changed by this documentation package.

The [official Space Mission Design Game Resources tab](https://www.spaceappschallenge.org/2026/challenges/space-mission-design-game/?tab=resources) lists GMAT and links to the [NASA software catalogue entry](https://software.nasa.gov/software/GSC-19468-1). GMAT's application README identifies [nasa/GMAT](https://github.com/nasa/GMAT) as a source distribution. The included challenge evidence records its retrieval time and links. This package prepares use of that resource; it does not claim the GMAT orbit solver was run or that game integration, award eligibility or an award has been verified.
